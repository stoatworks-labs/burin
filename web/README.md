# The Rasterizer web demo

The plugin's idea, running at **rasterizer.stoatworks-labs.com**. Drop your own
SVG on it and it draws it — which is the demo, because a plugin whose whole job
is rendering somebody else's artwork is best argued for with the visitor's own.

    cd web
    cf-run npx wrangler deploy        # static-assets-only Worker

`public/example-plate.svg` is a copy of the one in `docs/`, regenerated by
`tools/make_example_svg.py`. Copy it across when it changes; nothing does it
automatically, because a build step for one file that changes once a year is a
build step nobody will remember exists.

## What is a port and what is not

**The scale ladder, the cache rule, the motion, the reveal timing and the style
selection are ports** of `source/Raster.cpp`, `source/Motion.cpp`,
`source/Reveal.cpp` and `source/Style.cpp`. They are the same arithmetic and the
demo's rebuild counter should track the plugin's on the same inputs.

**The rasteriser is not a port, and cannot be.** The plugin uses nanosvg; this
uses the browser's own SVG engine, because shipping a WebAssembly build of
nanosvg to draw a picture the browser can already draw would be a great deal of
work to arrive at a slightly worse result. What matters is that the demo makes
the same *decisions* — it re-rasterises at the snapped rung, it covers what is on
screen, it mutates the shape list to select fills and strokes and to dash the
reveal — and then hands the drawing to a rasteriser. That the rasteriser is
Chrome's rather than nanosvg's changes the pixels slightly and changes nothing
about the argument.

Two visible consequences of the difference, both stated in the demo's own help:

- **The browser renders `<text>`; the plugin does not.** A file with live text
  will look right here and come out missing in Resolume. The demo detects text
  and says so, loudly, for exactly this reason — it would otherwise be a way of
  recommending a file that then fails.
- **`<clipPath>`, `<mask>`, `<filter>`, `<pattern>` and `<use>`** are the same
  story.

## What the HUD is for

The readout in the corner is the point of the demo as much as the picture is: it
shows the requested scale, the rung it snapped to, the raster's size in pixels,
and how many times it has been rebuilt. Dragging the zoom and watching the
rebuild counter move in steps — rather than once per frame — is the argument
that the plugin is affordable, and it is much easier to believe seen than read.

Nothing is uploaded. The file is read with `FileReader` and stays in the tab.
